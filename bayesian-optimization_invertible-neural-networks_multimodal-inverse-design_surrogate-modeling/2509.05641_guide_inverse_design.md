# GUIDe: Generative and Uncertainty-Informed Inverse Design for On-Demand Nonlinear Functional Responses

- **arXiv**: [2509.05641](https://arxiv.org/abs/2509.05641)
- **Authors**: Haoxuan Dylan Mu, Mingjian Tang, Wei Gao, Wei "Wayne" Chen
- **Submitted**: 2025-09-06 (revised 2025-10-08)
- **Keywords**: bayesian optimization, invertible neural networks, multimodal inverse design, surrogate modeling

## Methods

GUIDe addresses the fundamental challenge that deep generative inverse design models can hallucinate infeasible designs or provide incomplete solution coverage, particularly for nonlinear functional responses (e.g., full stress-strain curves).

1. **Forward Surrogate Model**: Rather than learning a direct inverse mapping (response-to-design), GUIDe trains a forward surrogate that maps design parameters to nonlinear functional responses. This avoids the ill-posedness of the inverse mapping while still enabling inverse queries via search over the design space.

2. **Probabilistic Confidence Evaluation**: Each candidate design generated during inverse queries is evaluated not only for target match quality but also for the model's prediction confidence. The forward surrogate provides uncertainty estimates that flag unreliable predictions, preventing hallucinated designs from being recommended.

3. **MCMC-Based Design Space Exploration**: Given a target nonlinear response and a user-specified tolerance, GUIDe employs Markov chain Monte Carlo sampling to explore the design space. The sampler targets the posterior distribution of designs consistent with the target response, naturally capturing multimodal solutions (the one-to-many nature of inverse problems).

4. **Out-of-Distribution Detection**: A key innovation is the ability to detect when a target specification lies outside the achievable design space. Standard generative models produce outputs regardless of feasibility; GUIDe's uncertainty-informed framework can abstain when confidence is insufficient, preventing costly fabrication of infeasible designs.

5. **Benchmarking Against Generative Baselines**: The paper compares against conditional VAEs, conditional GANs, and invertible neural network baselines, demonstrating that forward-model-based approaches with principled uncertainty handling outperform direct inverse mappings for nonlinear functional targets.

## Conclusion

GUIDe demonstrates that the combination of a forward surrogate model with MCMC sampling and uncertainty-informed filtering provides a more reliable approach to inverse design than direct generative inverse mappings. The framework successfully handles the one-to-many ambiguity of inverse problems by generating diverse design candidates while simultaneously filtering out hallucinated or infeasible solutions through confidence thresholds. The approach is validated on mechanical metamaterial design and spectral design problems, showing superior coverage of the solution space and fewer infeasible recommendations compared to standard deep generative approaches.

```python
import numpy as np
import torch
import torch.nn as nn

class ForwardSurrogate(nn.Module):
    def __init__(self, design_dim, response_dim, hidden=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(design_dim, hidden), nn.SiLU(),
            nn.Linear(hidden, hidden), nn.SiLU(),
            nn.Linear(hidden, hidden), nn.SiLU(),
        )
        self.mu_head = nn.Linear(hidden, response_dim)
        self.logvar_head = nn.Linear(hidden, response_dim)

    def forward(self, x):
        h = self.net(x)
        mu = self.mu_head(h)
        logvar = self.logvar_head(h)
        return mu, logvar

    def nll_loss(self, x, y):
        mu, logvar = self.forward(x)
        var = torch.exp(logvar) + 1e-6
        return 0.5 * torch.mean(logvar + (y - mu) ** 2 / var)

class GUIDeSampler:
    def __init__(self, model, design_bounds, target, tolerance=0.05,
                 confidence_threshold=2.0):
        self.model = model
        self.bounds_lo, self.bounds_hi = design_bounds
        self.target = torch.tensor(target, dtype=torch.float32)
        self.tolerance = tolerance
        self.conf_threshold = confidence_threshold

    def log_likelihood(self, design):
        with torch.no_grad():
            mu, logvar = self.model(design.unsqueeze(0))
            std = torch.exp(0.5 * logvar).squeeze(0)
            mu = mu.squeeze(0)
        residual = torch.norm(mu - self.target) / len(self.target)
        avg_std = torch.mean(std)
        if avg_std > self.conf_threshold:
            return -1e10
        return -residual.item() / self.tolerance

    def mcmc_sample(self, n_samples=1000, burn_in=500, step_size=0.02):
        dim = len(self.bounds_lo)
        current = torch.rand(dim) * (self.bounds_hi - self.bounds_lo) + self.bounds_lo
        current_ll = self.log_likelihood(current)
        samples = []
        for i in range(n_samples + burn_in):
            proposal = current + step_size * torch.randn(dim)
            proposal = torch.clamp(proposal, self.bounds_lo, self.bounds_hi)
            proposal_ll = self.log_likelihood(proposal)
            if np.log(np.random.rand()) < proposal_ll - current_ll:
                current = proposal
                current_ll = proposal_ll
            if i >= burn_in:
                samples.append(current.clone())
        return torch.stack(samples)
```
