# Using Deep Learning to Design High Aspect Ratio Fusion Devices

- **arXiv**: [2409.00564](https://arxiv.org/abs/2409.00564)
- **Authors**: P. Curvo, D. R. Ferreira, R. Jorge
- **Submitted**: 2024-08-31 (published in Journal of Plasma Physics, 2025)
- **Keywords**: mixture density networks, multimodal inverse design, physics-informed, surrogate modeling

## Methods

This paper applies Mixture Density Networks (MDNs) to the inverse design of stellarator fusion devices, explicitly addressing the non-uniqueness of the inverse mapping from desired plasma properties to device geometry.

1. **Forward Model as Surrogate**: A neural network surrogate is trained to predict plasma confinement properties (quasi-symmetry metrics, rotational transform profiles) from stellarator coil geometry parameters. This forward surrogate replaces computationally expensive magnetohydrodynamic (MHD) equilibrium calculations.

2. **Mixture Density Network for Inverse Mapping**: Rather than learning a deterministic inverse mapping (which would fail due to non-uniqueness), an MDN outputs a mixture of Gaussians representing the full conditional distribution of design parameters given a target property specification. Each mixture component corresponds to a distinct family of solutions in the design space.

3. **Handling Many-to-One Ambiguity**: The stellarator design problem is inherently many-to-one: multiple coil configurations can produce similar magnetic field properties. The MDN's mixture components capture these distinct solution families. The number of components is selected based on the expected multiplicity of the inverse mapping.

4. **Physics-Informed Constraints**: The training data is generated from physics-based MHD simulations, ensuring that all solutions respect fundamental plasma physics constraints. The network architecture and training procedure enforce physical bounds on design parameters (coil current limits, minimum coil-to-plasma distances, aspect ratio constraints).

5. **Probabilistic Sampling and Selection**: Given a target set of plasma properties, the MDN provides a full probability distribution over possible designs. The designer can sample multiple candidates, evaluate each against additional criteria (engineering feasibility, cost), and select the most practical solution from the physically valid set.

## Conclusion

The MDN-based approach successfully captures the multimodal nature of stellarator inverse design, generating diverse candidate coil configurations for target plasma properties. The probabilistic framework provides explicit quantification of design ambiguity: narrow mixture components indicate regions where the design is well-determined, while broad or multi-peaked distributions signal significant ambiguity requiring additional selection criteria. The physics-informed training data ensures all proposed designs are physically valid. The approach reduces the design iteration time from hours (MHD simulations) to milliseconds (MDN inference), enabling rapid exploration of the design space for fusion reactor optimization.

```python
import torch
import torch.nn as nn
import numpy as np

class MixtureDensityNetwork(nn.Module):
    def __init__(self, input_dim, output_dim, n_components=5, hidden=256):
        super().__init__()
        self.output_dim = output_dim
        self.n_components = n_components
        self.backbone = nn.Sequential(
            nn.Linear(input_dim, hidden), nn.SiLU(),
            nn.Linear(hidden, hidden), nn.SiLU(),
            nn.Linear(hidden, hidden), nn.SiLU(),
        )
        self.pi_head = nn.Linear(hidden, n_components)
        self.mu_head = nn.Linear(hidden, n_components * output_dim)
        self.sigma_head = nn.Linear(hidden, n_components * output_dim)

    def forward(self, x):
        h = self.backbone(x)
        pi = torch.softmax(self.pi_head(h), dim=-1)
        mu = self.mu_head(h).view(-1, self.n_components, self.output_dim)
        sigma = torch.exp(self.sigma_head(h)).view(
            -1, self.n_components, self.output_dim
        )
        return pi, mu, sigma

    def mdn_loss(self, x, y):
        pi, mu, sigma = self.forward(x)
        y_expanded = y.unsqueeze(1).expand_as(mu)
        log_probs = -0.5 * (
            torch.log(2 * np.pi * sigma**2) + (y_expanded - mu)**2 / sigma**2
        ).sum(dim=-1)
        log_pi = torch.log(pi + 1e-8)
        log_mixture = torch.logsumexp(log_pi + log_probs, dim=-1)
        return -log_mixture.mean()

    @torch.no_grad()
    def sample(self, x, n_samples=10):
        pi, mu, sigma = self.forward(x)
        batch_size = x.shape[0]
        samples = []
        for _ in range(n_samples):
            component = torch.multinomial(pi, 1).squeeze(-1)
            idx = component.unsqueeze(-1).unsqueeze(-1).expand(
                batch_size, 1, self.output_dim
            )
            selected_mu = mu.gather(1, idx).squeeze(1)
            selected_sigma = sigma.gather(1, idx).squeeze(1)
            sample = selected_mu + selected_sigma * torch.randn_like(selected_mu)
            samples.append(sample)
        return torch.stack(samples, dim=1)

    @torch.no_grad()
    def mode_analysis(self, x):
        pi, mu, sigma = self.forward(x)
        dominant = torch.argmax(pi, dim=-1)
        entropy = -(pi * torch.log(pi + 1e-8)).sum(dim=-1)
        return {
            'mixing_weights': pi,
            'means': mu,
            'stds': sigma,
            'dominant_mode': dominant,
            'ambiguity': entropy,
        }
```
