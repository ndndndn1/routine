# Generative Inverse Design with Abstention via Diagonal Flow Matching

- **arXiv**: [2603.15925](https://arxiv.org/abs/2603.15925)
- **Authors**: Miguel de Campos, Werner Krebs, Hanno Gottschalk
- **Submitted**: 2026-03-16
- **Keywords**: invertible neural networks, multimodal inverse design, tandem structure

## Methods

This paper proposes Diagonal Flow Matching (Diag-CFM) for generative inverse design, addressing a critical instability in standard conditional flow matching when applied to inverse problems.

1. **Problem Identification -- Coordinate Sensitivity**: Standard CFM pairs labels (target responses) with design parameters and learns a flow from noise to designs conditioned on labels. The authors show this formulation is highly sensitive to the arbitrary ordering and scaling of design coordinates, leading to unstable training and poor reconstruction accuracy.

2. **Diagonal Flow Matching (Diag-CFM)**: A zero-anchoring strategy pairs design coordinates with noise and labels with zero. This reformulation makes the learning problem provably invariant to coordinate permutations and scaling. The flow field only needs to transport design-related dimensions while labels remain anchored, dramatically simplifying the learning task.

3. **Bidirectional Design-Response Mapping**: The architecture learns both forward (design-to-response) and inverse (response-to-design) mappings through the flow formulation. This is analogous to the tandem structure but implemented via continuous normalizing flows rather than separate forward/inverse networks. The invertibility of the flow ensures consistency between the two directions.

4. **Architecture-Intrinsic Uncertainty Metrics**: Two uncertainty measures are derived from the flow structure without additional model components:
   - **Zero-Deviation**: Measures how far the label dimensions deviate from zero in the generated sample, indicating reconstruction fidelity.
   - **Self-Consistency**: Generates multiple candidates for the same target and measures their consistency through round-trip evaluation.

5. **Practical Capabilities from Uncertainty**: The uncertainty metrics enable three operational modes: (a) selecting the best candidate from multiple generations, (b) abstaining from unreliable predictions (out-of-distribution detection), and (c) detecting infeasible target specifications.

## Conclusion

Diagonal Flow Matching achieves order-of-magnitude improvements in round-trip accuracy over standard CFM and invertible neural network baselines across design dimensions up to P=100. The zero-anchoring strategy resolves the coordinate sensitivity that plagued previous flow-based inverse design methods. The architecture-intrinsic uncertainty metrics (Zero-Deviation and Self-Consistency) provide practical mechanisms for managing the one-to-many ambiguity of inverse problems without requiring external calibration or ensemble methods. Validated on airfoil design, gas turbine combustor design, and an analytical benchmark with scalable design dimensions, Diag-CFM demonstrates that careful formulation of the flow matching objective is critical for inverse design applications.

import torch
import torch.nn as nn

class DiagonalFlowMatching(nn.Module):
    def __init__(self, design_dim, label_dim, hidden=256, n_layers=4):
        super().__init__()
        input_dim = design_dim + label_dim + 1
        layers = [nn.Linear(input_dim, hidden), nn.SiLU()]
        for _ in range(n_layers - 1):
            layers += [nn.Linear(hidden, hidden), nn.SiLU()]
        layers.append(nn.Linear(hidden, design_dim + label_dim))
        self.velocity_net = nn.Sequential(*layers)
        self.design_dim = design_dim
        self.label_dim = label_dim

    def velocity(self, x, t):
        t_embed = t.unsqueeze(-1) if t.dim() == 1 else t
        inp = torch.cat([x, t_embed], dim=-1)
        return self.velocity_net(inp)

    def diagonal_training_loss(self, designs, labels):
        batch_size = designs.shape[0]
        t = torch.rand(batch_size, 1, device=designs.device)
        noise_design = torch.randn_like(designs)
        zero_label = torch.zeros_like(labels)
        x0_design = noise_design
        x0_label = zero_label
        x1_design = designs
        x1_label = labels
        xt_design = (1 - t) * x0_design + t * x1_design
        xt_label = (1 - t) * x0_label + t * x1_label
        xt = torch.cat([xt_design, xt_label], dim=-1)
        target_velocity = torch.cat([
            x1_design - x0_design,
            x1_label - x0_label
        ], dim=-1)
        pred_velocity = self.velocity(xt, t.squeeze(-1))
        return torch.mean((pred_velocity - target_velocity) ** 2)

    @torch.no_grad()
    def generate(self, labels, n_steps=100, n_candidates=5):
        batch = labels.shape[0]
        all_candidates = []
        for _ in range(n_candidates):
            noise = torch.randn(batch, self.design_dim, device=labels.device)
            zeros = torch.zeros(batch, self.label_dim, device=labels.device)
            x = torch.cat([noise, zeros], dim=-1)
            dt = 1.0 / n_steps
            for step in range(n_steps):
                t = torch.full((batch,), step * dt, device=labels.device)
                v = self.velocity(x, t)
                x = x + v * dt
            designs = x[:, :self.design_dim]
            label_dev = x[:, self.design_dim:]
            all_candidates.append((designs, label_dev))
        return all_candidates

    def zero_deviation(self, label_dev):
        return torch.norm(label_dev, dim=-1)

    def self_consistency(self, candidates_list):
        designs = torch.stack([c[0] for c in candidates_list])
        return torch.std(designs, dim=0).mean(dim=-1)
