# Combining Flow Matching and Transformers for Efficient Solution of Bayesian Inverse Problems

- **arXiv**: [2503.01375](https://arxiv.org/abs/2503.01375)
- **Authors**: Daniil Sherki, Ivan Oseledets, Ekaterina Muravleva
- **Submitted**: 2025-03-03
- **Keywords**: bayesian adaptive design, invertible neural networks, Transformer-Specific Attribution

## Methods

This paper combines Conditional Flow Matching (CFM) with transformer-based architectures for fast posterior sampling in Bayesian inverse problems, replacing expensive MCMC methods with amortized inference.

1. **Conditional Flow Matching as Invertible Mapping**: CFM learns a continuous normalizing flow (a class of invertible neural networks) that transforms a simple base distribution (Gaussian) into the posterior distribution conditioned on observations. The flow provides a bijective mapping between latent space and parameter space, enabling exact density evaluation and efficient sampling.

2. **Transformer Architecture for Variable Observations**: The transformer backbone processes a variable number of observations using self-attention, creating a summary representation that conditions the flow. This is critical for inverse problems where the number of measurements varies across experimental settings.

3. **Amortized Posterior Inference**: Once trained on simulated data (parameter-observation pairs from the forward model), the network generates posterior samples for new observations in a single forward pass. This amortization provides up to 2000x speedup compared to MCMC.

4. **Application to PDE-Constrained Inverse Problems**: The method is validated on Darcy flow PDE inversion, where the goal is to infer the permeability field from sparse pressure measurements. The transformer naturally handles different observation configurations without retraining.

5. **Multimodal Posterior Capture**: The flow matching framework can represent complex, multimodal posteriors that arise in ill-posed inverse problems where multiple parameter configurations explain the observations equally well. The transformer's attention mechanism helps identify which observations are most informative for disambiguating the posterior.

## Conclusion

The CFM-transformer combination provides efficient and flexible posterior sampling for Bayesian inverse problems, achieving orders-of-magnitude speedup over MCMC while maintaining posterior quality. The transformer architecture's ability to handle variable-length observation sequences makes the approach highly practical for real-world inverse problems where experimental configurations vary. The flow-based formulation captures multimodal posteriors that arise from the one-to-many nature of inverse problems, providing full uncertainty quantification rather than point estimates. The approach demonstrates that modern generative modeling techniques (flow matching) combined with expressive architectures (transformers) can effectively amortize the cost of Bayesian inference in PDE-constrained settings.

import torch
import torch.nn as nn

class ObservationTransformer(nn.Module):
    def __init__(self, obs_dim, d_model=128, nhead=4, n_layers=3):
        super().__init__()
        self.embed = nn.Linear(obs_dim, d_model)
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=nhead, dim_feedforward=256,
            batch_first=True, activation='gelu'
        )
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers=n_layers)
        self.pool = nn.Linear(d_model, d_model)

    def forward(self, observations, mask=None):
        h = self.embed(observations)
        h = self.encoder(h, src_key_padding_mask=mask)
        summary = h.mean(dim=1)
        return self.pool(summary)

class ConditionalFlowMatching(nn.Module):
    def __init__(self, param_dim, cond_dim, hidden=256, n_layers=4):
        super().__init__()
        layers = [nn.Linear(param_dim + cond_dim + 1, hidden), nn.SiLU()]
        for _ in range(n_layers - 1):
            layers += [nn.Linear(hidden, hidden), nn.SiLU()]
        layers.append(nn.Linear(hidden, param_dim))
        self.velocity = nn.Sequential(*layers)
        self.param_dim = param_dim

    def forward(self, x, t, cond):
        t_inp = t.unsqueeze(-1) if t.dim() == 1 else t
        inp = torch.cat([x, cond, t_inp], dim=-1)
        return self.velocity(inp)

    def cfm_loss(self, x0, x1, cond):
        batch = x0.shape[0]
        t = torch.rand(batch, 1, device=x0.device)
        xt = (1 - t) * x0 + t * x1
        target_v = x1 - x0
        pred_v = self.forward(xt, t, cond)
        return torch.mean((pred_v - target_v) ** 2)

    @torch.no_grad()
    def sample(self, cond, n_samples=100, n_steps=50):
        z = torch.randn(n_samples, self.param_dim, device=cond.device)
        cond_exp = cond.unsqueeze(0).expand(n_samples, -1)
        dt = 1.0 / n_steps
        x = z
        for step in range(n_steps):
            t = torch.full((n_samples, 1), step * dt, device=z.device)
            v = self.forward(x, t, cond_exp)
            x = x + v * dt
        return x

class BayesianInverseCFMT(nn.Module):
    def __init__(self, obs_dim, param_dim, d_model=128):
        super().__init__()
        self.obs_encoder = ObservationTransformer(obs_dim, d_model)
        self.flow = ConditionalFlowMatching(param_dim, d_model)

    def loss(self, observations, params, mask=None):
        cond = self.obs_encoder(observations, mask)
        x0 = torch.randn_like(params)
        return self.flow.cfm_loss(x0, params, cond)

    @torch.no_grad()
    def posterior_samples(self, observations, n_samples=500, mask=None):
        cond = self.obs_encoder(observations.unsqueeze(0), mask)
        return self.flow.sample(cond.squeeze(0), n_samples)
