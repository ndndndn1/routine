# Sensitivity-Constrained Fourier Neural Operators for Forward and Inverse Problems in Parametric Differential Equations

- **arXiv**: [2505.08740](https://arxiv.org/abs/2505.08740)
- **Authors**: Abdolmehdi Behroozi, Chaopeng Shen, Daniel Kifer
- **Submitted**: 2025-05 (ICLR 2025)
- **Keywords**: physics-informed, sensitivity-aware sampling, surrogate modeling

## Methods

SC-FNO integrates sensitivity analysis directly into neural operator training, ensuring that the surrogate model captures not only the forward solution but also its derivatives with respect to physical parameters.

1. **Fourier Neural Operator Baseline**: The method builds on the Fourier Neural Operator (FNO) architecture, which learns mappings between function spaces by operating in the Fourier domain. FNO serves as a fast surrogate for PDE solvers, enabling rapid forward evaluation.

2. **Sensitivity Constraint (du/dp)**: The key innovation is adding a regularization term that penalizes discrepancies between the surrogate's parameter sensitivities (du/dp) and the true sensitivities computed from PDE solutions. This ensures the surrogate correctly models how solution fields change with respect to physical parameters, not just the solutions themselves.

3. **Dual Benefits for Forward and Inverse Problems**: Accurate sensitivity information improves both forward prediction (especially in extrapolation and under parameter perturbation) and inverse parameter estimation (where gradient-based optimization relies on accurate du/dp). The sensitivity constraint acts as a physics-informed regularizer that prevents overfitting to training data distribution.

4. **Handling High-Dimensional Parameter Spaces**: The method scales to problems with up to 82 parameters, where standard FNOs degrade due to curse of dimensionality. The sensitivity constraint provides additional supervision signal that compensates for the sparse sampling of high-dimensional parameter spaces.

5. **Addressing Concept Drift**: When the underlying parameter distribution shifts between training and deployment (concept drift), sensitivity-constrained models maintain accuracy because they capture the local landscape of the solution manifold rather than just point predictions.

## Conclusion

SC-FNO demonstrates that incorporating parameter sensitivity (du/dp) as a training constraint yields neural operator surrogates that are more accurate, more robust to distribution shift, and better suited for inverse problems. The sensitivity-constrained models outperform standard FNOs across multiple PDE benchmarks, with particularly significant gains in high-dimensional parameter spaces and inverse problem settings. Published at ICLR 2025, the work establishes sensitivity analysis as a first-class citizen in neural operator training, bridging the gap between surrogate accuracy and the specific demands of downstream inverse design and optimization tasks.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SpectralConv2d(nn.Module):
    def __init__(self, in_channels, out_channels, modes1, modes2):
        super().__init__()
        self.modes1 = modes1
        self.modes2 = modes2
        scale = 1 / (in_channels * out_channels)
        self.weights1 = nn.Parameter(
            scale * torch.rand(in_channels, out_channels, modes1, modes2, 2)
        )
        self.weights2 = nn.Parameter(
            scale * torch.rand(in_channels, out_channels, modes1, modes2, 2)
        )

    def compl_mul2d(self, inp, weights):
        return torch.einsum("bixy,ioxy->boxy", inp, torch.view_as_complex(weights))

    def forward(self, x):
        x_ft = torch.fft.rfft2(x)
        out_ft = torch.zeros_like(x_ft)
        out_ft[:, :, :self.modes1, :self.modes2] = self.compl_mul2d(
            x_ft[:, :, :self.modes1, :self.modes2], self.weights1
        )
        out_ft[:, :, -self.modes1:, :self.modes2] = self.compl_mul2d(
            x_ft[:, :, -self.modes1:, :self.modes2], self.weights2
        )
        return torch.fft.irfft2(out_ft, s=(x.size(-2), x.size(-1)))

class SensitivityConstrainedFNO(nn.Module):
    def __init__(self, param_dim, modes=12, width=32, n_layers=4):
        super().__init__()
        self.lift = nn.Linear(param_dim + 2, width)
        self.convs = nn.ModuleList([
            SpectralConv2d(width, width, modes, modes)
            for _ in range(n_layers)
        ])
        self.ws = nn.ModuleList([
            nn.Conv2d(width, width, 1)
            for _ in range(n_layers)
        ])
        self.project = nn.Sequential(
            nn.Linear(width, 128), nn.GELU(),
            nn.Linear(128, 1),
        )

    def forward(self, params, grid):
        batch = params.shape[0]
        nx, ny = grid.shape[-2], grid.shape[-1]
        p = params.unsqueeze(-1).unsqueeze(-1).expand(batch, -1, nx, ny)
        x = torch.cat([p, grid], dim=1).permute(0, 2, 3, 1)
        x = self.lift(x).permute(0, 3, 1, 2)
        for conv, w in zip(self.convs, self.ws):
            x = F.gelu(conv(x) + w(x)) + x
        x = x.permute(0, 2, 3, 1)
        return self.project(x).squeeze(-1)

    def sensitivity_loss(self, params, grid, u_true, du_dp_true):
        params.requires_grad_(True)
        u_pred = self.forward(params, grid)
        du_dp_pred = torch.autograd.grad(
            u_pred.sum(), params, create_graph=True
        )[0]
        data_loss = F.mse_loss(u_pred, u_true)
        sens_loss = F.mse_loss(du_dp_pred, du_dp_true)
        return data_loss + 0.1 * sens_loss
```
